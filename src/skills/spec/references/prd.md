# Product Requirements Document

Save PRDs to `docs/specs/YYYY-MM-DD-<topic>.md`.

## Metadata Header

```markdown
# <Topic>

**Date:** YYYY-MM-DD
**Type:** spec
**Status:** active
**Tracker:** [tracker reference, if published]
**Related:** [link to design, if it exists]
```

## Required Sections

- **Problem and evidence**
- **Target users**
- **Outcomes and success measures**
- **Constraints and assumptions**
- **User-facing solution** -- intended experience and behavior without technical implementation
- **Scope** -- in-scope capabilities and explicit non-goals
- **User journeys** -- primary, failure, and recovery paths
- **User stories and acceptance criteria**
- **Product requirements** -- cross-cutting behavior, business rules, permissions, and external obligations
- **Dependencies**
- **Open questions**

Acceptance criteria must be observable without prescribing architecture or implementation.
